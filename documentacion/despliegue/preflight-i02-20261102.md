## Respaldo exacto preparado — **requiere nueva autorización para ejecutarlo**

Detener previamente todas las API escritoras y cajas. Usar el mismo contenedor y la misma base ya verificados. El archivo queda fuera de Git en `.local-backups/`, carpeta cuya exclusión en `.gitignore` se comprobó. Ejecutar desde PowerShell en la raíz del repositorio:

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$fileName = "i02-before-$stamp.dump"
$containerFile = "/tmp/$fileName"
$localFile = Join-Path (Resolve-Path '.local-backups').Path $fileName
if (Test-Path -LiteralPath $localFile) { throw 'El respaldo ya existe.' }
docker exec $container pg_dump -U postgres -d $database -Fc -f $containerFile
if ($LASTEXITCODE -ne 0) { throw 'Falló pg_dump; no aplicar I02.' }
$toc = @(docker exec $container pg_restore --list $containerFile)
if ($LASTEXITCODE -ne 0 -or
    @($toc | Where-Object { $_ -like '*dbname: carnicerias_test_visual*' }).Count -ne 1 -or
    @($toc | Where-Object { $_ -like '*Format: CUSTOM*' }).Count -ne 1) {
    throw 'El archivo no se identifica como respaldo custom de la base autorizada.'
}
docker exec $container pg_restore --file=/dev/null $containerFile
if ($LASTEXITCODE -ne 0) { throw 'El archivo no pudo leerse completamente.' }
docker cp "${container}:$containerFile" $localFile
if ($LASTEXITCODE -ne 0) { throw 'No se pudo copiar el respaldo fuera del contenedor.' }
$localBytes = (Get-Item -LiteralPath $localFile).Length
if ($localBytes -le 0) { throw 'El respaldo local está vacío.' }
$containerHash = ((docker exec $container sha256sum $containerFile) | Select-Object -First 1).Split(' ')[0]
if ($LASTEXITCODE -ne 0) { throw 'No se pudo calcular el hash del contenedor.' }
$localHash = (Get-FileHash -LiteralPath $localFile -Algorithm SHA256).Hash
if ($containerHash.ToUpperInvariant() -ne $localHash.ToUpperInvariant()) {
    throw 'El archivo local difiere del archivo del contenedor.'
}
Write-Output "Respaldo verificado: $localFile"
```

`pg_dump -Fc` genera una copia lógica consistente de **esta base completa**, incluidos los esquemas POS y central. `pg_restore --list` comprueba el catálogo del archivo y `--file=/dev/null` lee su contenido sin conectarse a la base; hash y tamaño comprueban la copia local. **Estas verificaciones no sustituyen una restauración real de ensayo**, que queda fuera de alcance porque no se permite crear otra base. [PostgreSQL 16: pg_dump](https://www.postgresql.org/docs/16/app-pgdump.html) y [pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html).

## Reversión, riesgos y ventana

- El `Down` de I02 lanza `NotSupportedException` para impedir perder estado y auditoría. **No** usar `dotnet ef database update` hacia la migración anterior.
- Si la migración falla antes del commit, su transacción revierte el esquema y el backfill. Mantener escritores apagados, inspeccionar error y no repetir sin resolver el bloqueo.
- Si se detecta un problema **antes de reabrir cajas**, con autorización específica, detener escritores y restaurar el archivo en **la misma base existente**, sin `--create`. Usar el archivo local y las variables del bloque de respaldo:

  ```powershell
  docker cp $localFile "${container}:$containerFile"
  if ($LASTEXITCODE -ne 0) { throw 'No se pudo copiar el respaldo para restauración.' }
  $restoreHash = ((docker exec $container sha256sum $containerFile) | Select-Object -First 1).Split(' ')[0]
  if ($LASTEXITCODE -ne 0 -or $restoreHash.ToUpperInvariant() -ne $localHash.ToUpperInvariant()) {
      throw 'El respaldo de restauración no coincide con la copia verificada.'
  }
  docker exec $container pg_restore -U postgres -d $database --clean --if-exists `
      --single-transaction --exit-on-error $containerFile
  if ($LASTEXITCODE -ne 0) { throw 'La restauración falló; mantener las cajas cerradas.' }
  ```

  Esta operación reemplaza datos y **no está autorizada ahora**.
- Si ya hubo ventas/pagos tras abrir cajas, restaurar el snapshot perdería esas operaciones. Detener escritores y diseñar una reparación hacia adelante o conciliación antes de cualquier reversión.
- El bloqueo `SHARE ROW EXCLUSIVE` de I02 impide ventas/recepciones concurrentes durante el backfill y la creación de índices. El tiempo real depende de los conteos aún no disponibles. Reservar **provisionalmente 30 minutos de indisponibilidad de laboratorio** para detener procesos, respaldo, migración y comprobaciones; no es una medición ni un límite garantizado.
